# Розподіл парних і непарних чисел у трьох потоках

Консольна програма на C# виконує завдання з використанням **трьох потоків `Thread`** та синхронізації спільних ресурсів через **`lock`**.

## Запуск

Потрібен **.NET SDK 10**. Завантажте репозиторій через **Code → Download ZIP**, розпакуйте та відкрийте термінал у папці проєкту:

```powershell
dotnet build
dotnet run
```

## Як виконано завдання

1. Створюється `int[] fullArray = new int[1000]` і заповнюється випадковими числами **від 1 до 10 включно** через `Random.Next(1, 11)`.
2. Створюються саме `List<int> evenList` і `List<int> oddList`.
3. Створюються рівно три об’єкти `Thread`. Кожен виконує ту саму функцію `DistributeNumbers`.
4. Спільний індекс `nextIndex` визначає наступний елемент. Під блокуванням потік перевіряє межі масиву, бере число та збільшує індекс. Тому кожна позиція обробляється лише один раз.
5. Потік перевіряє `number % 2` та додає число у відповідний список під його блокуванням.
6. Головний потік запускає всі три через `Start()` і очікує завершення всіх через `Join()`.
7. Після завершення обробки в консоль виводяться обидва списки, їхні розміри та загальна кількість **1000**. На початку також показано початковий масив для перевірки результатів.

Основний код: **[Program.cs](Program.cs)**. `Task`, `Parallel.For` та готове послідовне розділення колекцій у програмі не використовуються.

## Синхронізація

| Спільний ресурс | Захист | Для чого |
| --- | --- | --- |
| `nextIndex` та отримання наступного елемента | `lock (arrayLock)` | Унеможливлює отримання однієї позиції кількома потоками та вихід за межі масиву |
| `evenList.Add(number)` | `lock (evenLock)` | Захищає внутрішню структуру `List<int>` від одночасних змін |
| `oddList.Add(number)` | `lock (oddLock)` | Такий самий захист для непарних чисел |
| Перебір списків для виведення | Після всіх `Join()` | На цей момент жоден робочий потік уже не змінює дані |

Блокування не вкладені одне в одне: потік звільняє `arrayLock` перед додаванням у список. Тривалість кожної критичної секції мала. Генератор випадкових чисел використовується головним потоком ще до запуску робочих.

Однакові значення в початковому випадковому масиві зберігаються з усіма своїми повтореннями. Порядок чисел у списках може змінюватися через планування потоків; завдання не вимагає збереження початкового порядку. Розподіл роботи між трьома потоками також визначається планувальником і не обов’язково рівномірний.

## Перевірка

Збірка виконана без помилок та попереджень. Сценарій перевірки запускає реальну програму п’ять разів і для кожного запуску перевіряє:

- 1000 елементів початкового масиву та діапазон 1..10;
- лише парні значення в `evenList` і лише непарні в `oddList`;
- відповідність оголошених розмірів фактичним спискам;
- суму довжин списків 1000;
- точний збіг частот усіх десяти можливих значень між початковим масивом і результатами.

Порівняння частот виявляє втрату або зайве додавання елементів навіть тоді, коли загальна кількість випадково лишилася правильною.

Повторити перевірку після збірки у PowerShell:

```powershell
./scripts/Verify.ps1
```

Фактичний вивід першого запуску: [reports/run-output.txt](reports/run-output.txt). Результати всіх п’яти запусків: [reports/verification.txt](reports/verification.txt).

## Висновок

Три потоки спільно обробляють один масив. Синхронізація індексу забезпечує одноразову обробку кожної позиції, блокування списків захищає їх від конкурентних змін, а `Join()` дозволяє безпечно показати результат лише після завершення всієї роботи.
